# Mobile Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution method for this run:** native, in-session, phase-by-phase — supplied by the user's original migration brief ("do not stop after writing a plan... execute in small, verifiable phases, fixing errors as they occur... ask for approval before consequential production changes"). Each task below is committed separately so the branch stays bisectable.

**Goal:** Convert the existing flat static HTML/CSS/JS Quran app into an installable Android app (and an iOS project prepared to the extent a Linux machine allows) via Capacitor, without rewriting any existing business logic, without touching the (non-existent) backend, and without breaking the existing plain-web version of the app.

**Architecture:** Capacitor wraps the existing `index.html` + scripts unchanged in source. A new minimal build script copies the existing root-level `index.html`, `*.js`, and `*.css` files verbatim into a generated `www/` directory (gitignored), which becomes Capacitor's `webDir`. Source files keep their current flat paths — nothing is moved or renamed. A new, small, Capacitor-only bootstrap script is appended as the *last* `<script>` tag in `index.html`, guarded by `if (window.Capacitor)`, so the plain-browser version of the site is completely unaffected. Native Android/iOS platform folders (`android/`, `ios/`) are generated by the Capacitor CLI, not hand-built.

**Tech Stack:** Capacitor 7.x (current stable major, Node 22-compatible), `@capacitor/android`, `@capacitor/ios`, plugins `@capacitor/app`, `@capacitor/browser`, `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/network` — chosen because the audit found exactly these four native needs (hardware back button, opening the 8 outbound resource links outside the WebView, status-bar styling/safe-area, and offline detection for API failures) and nothing else (no camera, no push, no biometrics, no deep links — none of those are used by any existing feature).

**Spec:** User-supplied mobile-conversion brief (pasted in full in this conversation) + `docs/mobile-migration-audit.md` (Phase One findings this plan is grounded in).

## Global Constraints

- Preserve every existing filename and path at the repo root exactly as-is — no `src/`/`css/` reorg (explicitly declined by the user for this migration).
- Preserve the existing script load order inside `index.html`; the new Capacitor bootstrap script is appended, never inserted earlier.
- `npm start` (plain `python3 -m http.server 8000` dev flow) and `npm test` must keep working unmodified throughout.
- No secrets, signing keys, or credentials committed to git at any point.
- No SSL/certificate validation is ever bypassed; the only backend is the already-HTTPS public Al Quran Cloud API — no backend code changes.
- Android application ID: placeholder `com.example.qurankareem`, display name `Qur'an Kareem` — documented everywhere as a placeholder to replace before any real store submission (per user's choice to defer picking a permanent ID).
- Install only the 4 plugins named above — no plugin or permission not tied to an existing, audited feature.
- `www/` is a generated artifact (from the new build script), not hand-edited, and is gitignored.

## Review Focus

- **Hardware Android back button** on a non-home page exits the WebView/app instead of navigating back to the previous in-app page — the single highest-risk native-behavior gap, since this is an SPA with its own page stack `app.js` already manages in-memory. Covered by Task 5's back-button handler + manual back-navigation test matrix in Task 10.
- **Outbound resource links** (`islamic-resources.js`, 8 sites) opening *inside* the app's WebView with no visible way back, trapping the user on an external site. Covered by Task 5's `Browser` plugin interception + manual test in Task 10.
- **Audio interrupted by a phone call or another app** leaving the player in a stuck "playing" state with no resume/stop reconciliation. Covered by Task 10's manual audio-interruption test; no code change is planned unless the manual test reveals a stuck state.
- **Offline / API-unreachable state** (airplane mode, no signal) currently surfaces only as a generic `console.error` + thrown exception per `api-service.js:41-43`, with no user-facing message — covered by Task 6 (network status banner) and Task 10's offline manual test.
- **Status bar / notch overlap** on edge-to-edge Android devices, since the existing CSS was written for a browser viewport with no concept of a system status bar inset — covered by Task 7's safe-area CSS + manual visual check on an emulator/device in Task 10.

### Task 5: Native bootstrap script — back button, external links, status bar, splash

**Files:**
- Create: `capacitor-bootstrap.js` (root, alongside the other app scripts — same flat layout)
- Modify: `index.html` (append one `<script src="capacitor-bootstrap.js"></script>` as the last script tag)
- Modify: `scripts/build-web.js` is unaffected (it already copies every root `*.js`, so no change needed there)

**Interfaces:**
- Consumes: `window.Capacitor`, `@capacitor/app`'s `App.addListener('backButton', ...)`, `@capacitor/browser`'s `Browser.open({ url })`, `@capacitor/status-bar`'s `StatusBar.setOverlaysWebView`/`setStyle`, `@capacitor/splash-screen`'s `SplashScreen.hide()`.
- Produces: nothing other agent code depends on — this is a leaf integration script.

- [ ] **Step 1: Guard clause**

`capacitor-bootstrap.js` starts with `if (!window.Capacitor) return;`-equivalent top-level guard (an IIFE that returns early) so this script is a complete no-op when the site runs in a plain desktop/mobile browser.

- [ ] **Step 2: Back-button handling**

Register `App.addListener('backButton', ...)`. If a non-home `.page` is currently `active` (reuse `app.js`'s existing page-switch mechanism — check how `app.js` tracks the active page, e.g. its `showPage`/equivalent function, and call it to go to `homePage`) go to the home page; if already on the home page, call `App.exitApp()`. Any open modal (`tafseerModal`/`reciterModal` with a visible/open state) closes first, taking priority over page navigation, mirroring normal Android app conventions.

- [ ] **Step 3: Intercept outbound resource links**

Delegate a `click` listener on `document` that checks `event.target.closest('a[target="_blank"]')`; if found, `event.preventDefault()` and call `Browser.open({ url: link.href })` instead, so the 8 Islamic-resource links open in the system browser, not the app's WebView.

- [ ] **Step 4: Status bar + splash**

On `Capacitor`'s platform-ready event (`document.addEventListener('DOMContentLoaded', ...)` is sufficient since Capacitor injects itself before the WebView loads), call `StatusBar.setStyle({ style: Style.Dark })` (app has a light default theme per `styles.css` — confirm against the actual default theme value in `settings.js` and match, or make it track the existing theme-toggle) and `SplashScreen.hide()` once `app.js`'s initial render is done (reuse any existing "app ready"/initial-load-complete signal in `app.js`; if none exists, hide on `window.load`).

- [ ] **Step 5: Append the script tag**

In `index.html`, add `<script src="capacitor-bootstrap.js"></script>` as the very last line before `</body>`, after all 16 existing script tags — load order of existing scripts must not change.

- [ ] **Step 6: Rebuild and verify no desktop regression**

Run: `npm run build && npm start` (background), then open `http://127.0.0.1:8000/index.html` and confirm the page behaves exactly as before (the guard clause makes the new script inert outside Capacitor) with no console errors.

- [ ] **Step 7: Commit**

```bash
git add capacitor-bootstrap.js index.html
git commit -m "feat: add Capacitor bootstrap for back button, external links, status bar, splash screen"
```
